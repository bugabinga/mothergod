# The CLI half of the FIT matrix (ADR-0064): one behavior the genre shares per
# row, the genre being gzip, bzip2, xz, zstd, brotli and lz4. tests/fit_cli.rs
# probes each row against the built binary and fails when a recorded state
# disagrees with the observation, so a flip is a diff to this file.
# .github/scripts/status-data.py reads the same file: FIT is the `holds` rows
# over all rows.
#
# Format: id | state | behavior | citation | note
#   state     holds, gap, or declined. A declined row stays in the denominator
#             and has no probe; its note is the reason.
#   citation  the man page and section a row was read from, on the Ubuntu
#             runner (gzip 1.12, bzip2 1.0.8, xz 5.4.5, zstd 1.5.7, brotli
#             1.1.0, lz4 1.9.4), or the run that observed it. A tool that does
#             not document the behavior is not cited.
#   note      optional; where the genre splits, the split and the choice.
#
# Where a row names a flag, its probe spells the invocation as the genre does
# (`mothergod -c file`); a row holds only where it holds on every lane that can
# run the probe, and a lane that cannot run one leaves the row unmeasured there.

mode-d | holds | -d and --decompress select decompression | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -d |
stdout-c | holds | -c and --stdout write to stdout and leave the input alone | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -c |
keep-k | holds | -k and --keep are accepted and the input survives | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -k | the project keeps the input by default (source-kept), so -k is accepted and does nothing
force-f | holds | -f and --force overwrite an existing output file | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -f |
test-t | holds | -t and --test check a compressed file and write nothing | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -t |
list-l | declined | -l and --list print a compressed file's sizes without decompressing it | gzip(1), xz(1), zstd(1) OPTIONS -l | the genre splits three to three (bzip2, brotli, lz4 have none); -t -v says the sizes after a verified decode, and a listing that trusts the header is a second source for one number, wrong exactly when the frame is corrupt
verbose-v | holds | -v and --verbose are accepted and the data on stdout is unchanged | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -v |
quiet-q | holds | -q and --quiet are accepted and the data on stdout is unchanged | gzip(1), bzip2(1), xz(1), zstd(1), lz4(1) OPTIONS -q | brotli(1) takes -q as a quality; the only notice mothergod writes is -v's report, so -q cancels it and an error is always reported, where xz, zstd and lz4 also silence errors on a second -q
level-digit | gap | -1 selects a compression level | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -# | #983; mothergod has one tier until M5
help | holds | -h and --help print usage and exit 0 | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -h | the genre splits three to three on the stream (gzip, xz, zstd to stdout; bzip2, brotli, lz4 to stderr), the man pages are silent on it; the probe accepts either
version | holds | -V and --version print the version and exit 0 | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -V | #977; bzip2 alone writes it to stderr, the man pages are silent on the stream, the probe accepts either

stdin-dash | holds | the operand - names stdin | gzip(1) DESCRIPTION, xz(1) DESCRIPTION, zstd(1) DESCRIPTION, brotli(1) DESCRIPTION |
no-operand-stdio | holds | with no file operand, stdin is read and stdout written | gzip(1) DESCRIPTION, bzip2(1) DESCRIPTION, xz(1) DESCRIPTION, zstd(1) DESCRIPTION, brotli(1) DESCRIPTION |
bare-compresses | holds | with no mode flag and no operand, stdin is compressed to stdout | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) default mode is compression |
multiple-operands | holds | several file operands are processed in one run | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1) DESCRIPTION, lz4(1) -m |
unknown-option | holds | an unknown option exits nonzero and says why on stderr | observed on the runner: `T --frobnicate` exits 1 with stderr text for all six |
source-kept | holds | compressing a file leaves the source in place | zstd(1), brotli(1), lz4(1) keep by default; gzip(1), bzip2(1), xz(1) delete | the genre splits three to three; mothergod keeps, because a compressor that deletes its input is one bug from data loss
no-clobber | holds | an existing output file is not overwritten without -f | gzip(1), bzip2(1), xz(1), zstd(1), brotli(1), lz4(1) OPTIONS -f |

mtime-copied | holds | the output file carries the source's modification time | gzip(1) DESCRIPTION, bzip2(1) DESCRIPTION, xz(1) DESCRIPTION, brotli(1) OPTIONS -n |
mode-copied | holds | the output file carries the source's permission bits | gzip(1) DESCRIPTION, bzip2(1) DESCRIPTION, xz(1) DESCRIPTION, brotli(1) OPTIONS -n | unix only
concatenation | holds | concatenated compressed members decompress to the concatenated payloads | gzip(1) ADVANCED USAGE, bzip2(1) DESCRIPTION, xz(1) DESCRIPTION, zstd(1) DESCRIPTION, lz4(1) DESCRIPTION | ADR-0067
streaming-memory | holds | an input of any length is read one block at a time, so memory follows the block and not the input | bzip2(1) MEMORY MANAGEMENT, xz(1) DESCRIPTION Memory usage | the probe sees reads stop at one 16 MiB block while it encodes; the peak itself, under 1 GiB on 256 MiB plus one byte, is asserted weekly by .github/scripts/memory-check (#1109)
